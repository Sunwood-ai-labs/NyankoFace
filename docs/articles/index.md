# Field notes

NyankoFace is easier to operate when you understand why its parts exist. These pieces begin with a problem, follow the design decision, and end with links into the reference atlas and practical guides.

## Start with the idea

How one PostgreSQL event ledger makes views, completed downloads, and active
likes measurable, while calmer navigation, tablet-safe Spaces, MCP setup
guidance, and a saved logo exploration keep the visible surface reviewable.

### [NyankoFace v0.5.0: move state to a safer operating boundary](./nyankoface-v0-5-0.md)

How PostgreSQL-backed pipeline state, explicit legacy migration, fail-closed

How metric-backed discovery, immediate navigation feedback, Space readiness, readable code, and one shared identity make the hub feel faster without hiding the evidence.

How Pages, Pipelines, protected environment settings, portable Automations, and exact-head review evidence turn repositories into an auditable delivery workflow.
