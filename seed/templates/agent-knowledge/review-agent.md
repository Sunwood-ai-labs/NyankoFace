# 独立レビューで確認する証跡

独立レビューでは、実装担当の説明をそのまま要約するのではなく、要求と実際の差分を別々に確認します。

## レビューの順序

1. Issueの完了条件と禁止事項を読む
2. 変更ファイルとコミット履歴を確認する
3. テストを再実行し、失敗が隠されていないかを見る
4. UI変更は対象ビューポートのスクリーンショットで比較する
5. 未確認事項を明示して判定する

承認コメントには、確認したコミット、実行したコマンド、目視した画面を残します。推測と確認済みの事実を混ぜず、再現できない証跡を成功扱いにしません。

実装担当とレビュー担当のアカウントを分けることで、誰が変更し、誰が承認したかを履歴から追跡できます。
