# 小さな変更を安全に届ける

安全な実装は、巨大な差分を最後に一度だけ確認するのではなく、意図が一つの小さな変更へ分解するところから始まります。

## 実装の流れ

1. 再現条件と期待結果を固定する
2. 関係するコードと既存テストを読む
3. 最小の変更で失敗条件を解消する
4. 静的検査、単体テスト、対象画面の確認を行う
5. 差分を読み直してからコミットする

コミットメッセージは「何をしたか」だけでなく、変更の目的が分かる語を選びます。生成物や無関係な整形を混ぜず、問題が起きたときに一つずつ戻せる粒度を保ちます。

ブラウザーに関係する変更ではHTTP 200だけを成功条件にせず、操作と表示の両方を確認します。
